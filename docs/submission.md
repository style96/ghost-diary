## What I Built

A diary should have one author. Ghost Diary has an uninvited second one.

![Ghost Diary video title artwork: a notebook with a presence](https://raw.githubusercontent.com/style96/ghost-diary/main/deliverables/ghost-diary-demo.poster.png)

*Illustrated title card from the demo video. The video itself shows the real local application.*

You write about your day, save the page, and choose **Pass the night**. When you return to the entry, a sentence has appeared that you never wrote. The ghost reads the page and a little of your recent history before leaving its trace.

I wanted the unsettling moment to happen inside something familiar. No jump scare or monster. Just an ordinary page, an ordinary evening, and a line that doesn't belong.

The original is always preserved. You can compare the versions and restore your own words. Fiction can unsettle you without destroying your notebook.

To try it, open the demo, choose a page and select **Pass the night**. Watch the new ink appear, use **See what changed** to compare the versions, then select **Hear the ghost** if you want to hear the added sentence. No account or model download is needed to explore the recorded examples.

The recorded story follows a yellow umbrella across three pages: first beside the door, then missing from its hook, and finally locked in a cupboard. The first page establishes a bent spoke. On the second page, the original never mentions the umbrella, but Gemma recalls it from the previous entry:

> I examined the bent spoke of the umbrella.

On the third page, after the diarist locks the umbrella away, the ghost adds: “I straightened the bent spoke on the umbrella.” The older physical detail becomes evidence that the presence remembers—and can still reach it.

The three committed examples were generated by `gemma3:4b` in approximately 17.3, 3.7 and 21.1 seconds on the development machine. Those are observed request durations, not a latency guarantee. The repository includes exact prompts, raw replies and rejected candidates; the selected model sentences have not been rewritten.

### Giving the ghost a voice

The ghost's new sentence now appears with a short ink animation. It takes about 1.2 seconds to settle onto the page; reduced-motion preferences show the final text immediately.

After revealing an entry, select **Hear the ghost** to listen to its added sentence. Sound is optional and never autoplays. **Stop the ghost** rewinds it, and restoring the original, changing pages or opening **How it haunts** stops playback.

The three public-demo MP3 voices were generated during preparation with ElevenLabs using the premade Sarah voice and `eleven_v4` on October 31, 2026. They use a soft whisper delivery, without background music or added horror effects. Gemma generates the words; ElevenLabs generates the recorded narration. The official SDK sends only the three fictional ghost insertions with a whisper delivery tag, then saves bundled audio and a manifest that must match the exact displayed sentence.

The recordings are bundled with the public demo, so playback needs no live speech-generation API call. The local Windows application generates speech on the device for each new ghost insertion using Windows desktop speech and Python 3. Personal diary entries are not sent to ElevenLabs. The video uses that actual local Windows speech for the ghost moment, with separate ElevenLabs narration explaining the demonstration.

## How I Built It

The interface uses React and TypeScript, styled like a slightly weathered notebook. IndexedDB keeps the diary in the browser. A small Node server listens on loopback and sends generation requests to local Ollama, running Google's open-weight Gemma 3 model.

I started with a 1B model. It ran, but its prose was weak, so I tested the 4B variant. The early failure was more interesting than the first success: the model sometimes selected overlapping targets or tried to rewrite too much. That made preservation part of the architecture.

The model now selects a target from exact, unique sentences in the original and returns a structured edit. The application checks that output again before applying it. The original and ghost version remain separate. Late responses cannot overwrite a newer revision of the page.

Here is the actual edit saved for the second recorded page:

```json
{
  "kind": "insertAfter",
  "target": "The third hook beside the door was empty.",
  "text": "I examined the bent spoke of the umbrella."
}
```

That boundary matters more than asking the model to behave. A missing or ambiguous target is rejected; it never becomes permission to rewrite the whole page. If local generation fails, the app shows an error and keeps the original. It does not substitute a recorded response.

No vector database or agent framework was necessary for this build. The current original and up to three recent original entries supply the ghost's context. Earlier ghost text is excluded, so the model cannot treat its own inventions as the diarist's history. Codex helped build the software; Gemma performs the actual diary intervention.

To run the live version, install Node.js 24+ and Ollama, then:

```sh
git clone https://github.com/style96/ghost-diary.git
cd ghost-diary
ollama pull gemma3:4b
npm install
npm run build
npm start
```

Keep Ollama running and open `http://127.0.0.1:3001`. Write and save a page, then pass the night. The repository documents behavioral checks for original preservation, invalid model edits, stale responses and backup recovery.

## Why Does Open Innovation Matter?

Diary writing is personal. A local model lets the central interaction happen without sending those entries to a hosted model service. In local mode, the browser talks to a server on the same machine, and that server talks to local Ollama. There is no hosted inference API key.

The openness also changes who gets to shape the ghost. Its instructions are in the repository. The model name is configurable. Someone can change its tone, experiment with another compatible local model, or keep running their copy without a provider account. The diary can be exported as a plain JSON backup.

There is no per-request hosted AI fee in local mode, though hardware and electricity are real costs. I also tested the local application with my internet connection disconnected, and it continued working. Once the dependencies, model weights and production build are installed, the local experience does not need an internet connection.

There are boundaries: browser storage is not encrypted, and clearing it can delete the diary. The public website is separately hosted and serves fictional recorded data. Gemma is open-weight under its own license; the application's MIT license does not change the model terms.

That is the appeal of this particular ghost: it can inhabit the notebook without requiring the notebook to leave your computer.

## The Spirit of It

The moment I wanted is the empty hook. The diarist notices an absence; another voice remembers exactly what used to hang there. By the third page, a locked cupboard cannot keep that presence out. The notebook becomes evidence against its own author.

These are curated examples, not proof that every fresh generation will be equally effective. A future evaluation could measure how often the ghost recalls a concrete earlier detail while keeping its edit small and reversible. For this release, the story, original-preservation boundary and working local demonstration are complete.

If you were building a haunted diary, how much freedom would you give the model to change your words? I kept every edit small and reversible—I'd love to hear how you'd approach it.
